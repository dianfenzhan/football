# 魔镜方案

悬浮助手「魔镜」：FAQ 先答，答不上交给模型；模型只调一次，看整份 `doc/mirror.md` 加本次实时数据。不上向量库、Function Calling、Agent。

目标量级：每周 50～100 次提问。原则是**先保质量，再省 Token**——这个量级下模型费按周算只有几毛钱，不值得为省几分钱让答案变差。

## 1. 产品

- 全局悬浮球「魔镜」，点开半屏对话；顶部 3～4 个快捷问题（下一场什么时候、还差几人、怎么后补、我的数据），点了直接走 FAQ。
- 单次输入不超过 60 字。回答收到后前端按字打出。
- 每条回答可点「有用 / 没用」。
- 只回答本小程序怎么用，以及下一场、名额、天气、进球、助攻、出勤、鸽子。无关问题由模型按提示词礼貌拒绝。

## 2. 知识三层

| 层 | 文件 | 用途 |
| --- | --- | --- |
| FAQ | `doc/mirror-faq.json` | 优先。命中静态问题直接回答，命中实时问题查库填模板，不调模型 |
| 说明书 | `doc/mirror.md` | FAQ 没把握时，**整份**作为模型的固定说明 |
| 研发文档 | `doc/features.md` | 给人看，不给模型。改功能后据此更新上面两份 |

规则：

- FAQ 的 `answer` 口语、简短；数字和时间一律用 `answerTemplate` 的 `{{槽位}}` 现查现填。
- 每条实时 FAQ 都要有「没数据」时的兜底话术（如没有下一场、天气没取到）。
- `mirror.md` 不写任何具体数字；总长控制在 4000 字以内。

## 3. 一次提问的流程

```
问题（≤ 60 字）
 → 归一化（同义词：缺席→鸽子、报上→报名…）
 → FAQ 打分（bigram + 关键词）
      命中条件：最高分 ≥ 0.72，且比第二名高 ≥ 0.10
      ├─ 静态命中 → 直接回答
      ├─ 实时命中 → 查库 → 填模板 → 回答（没数据走兜底话术）
      └─ 不满足命中条件
           → 限流检查（本人当天 ≥ 15 次，或全站当天 ≥ 100 次 → 回固定提示）
           → 按总目录命中词决定查哪些实时数据（可多选，不命中就不查）
           → 调模型一次
 → 写 mirror_logs
```

总目录（`mirror.md` 里的表）现在**只用来决定查哪些数据**，不再决定给模型看哪段说明。

## 4. 每次调模型都带的上下文

| 内容 | 来源 | 说明 |
| --- | --- | --- |
| 当前时间 | 云函数 | 北京时间，如「2026-10-31 周六 13:55」，用来算「还有几天」「这周三」 |
| 提问人 | `users` | 姓名、所属球队、是否管理员、是否已建档。admin 模块靠「是否管理员」决定教不教 |
| 上一轮 | 前端传 | 上一问和上一答各截 100 字以内，用于「那后补呢」这类追问；新开对话不带 |
| 实时数据 | 按需查 | 见第 5 节，紧凑中文一行一项，不传原始 JSON |

## 5. 实时数据

都转成一行中文，不带 `_id`、`openid`、`avatarUrl`、时间戳；**不调 `readableAvatars`**（换头像临时链接慢且对文字无用）。

| 数据 | 内容与格式 | 来源 |
| --- | --- | --- |
| `next` | `下一场：{标题}，{周几 几点}，{地点}；报名方式：{分队/联合}；你：{已报 X 队/未报名}；名额：{各组 已报/上限，后补 N}` | 复用 `homeSummary` 里取最近一场的逻辑 |
| `weather` | `开赛 {HH}:00：{天气} {温度}°C 风{风力}；{前后两小时概况}` | 复用 `weather.js`（与 `activityWeather` 同源） |
| `stats` | `近3个月·全部球队｜进球前10：张三5、李四4…` 只放问到的那个榜 | 从 `homeSummary` 抽出的统计函数 |
| `me-stats` | `你（近3个月·全部球队）：进球1、助攻2、出勤6、鸽子0` | 同上；本人不在前 10 也能取到 |

`homeSummary` 内部的 `totals`、`attendanceRows` 已包含所有人。把这段统计抽成公共函数（如 `boardTotals(span, teamId, now)`），`homeSummary` 和魔镜共用；魔镜从结果里直接取本人一行。

时间范围和球队：问题里出现「半年 / 今年 / 一年」「jiong / 浦东」时换对应 `span`、`teamId`，否则默认近 3 个月、全部球队，并在回答里说出范围。

## 6. 模型调用

| 项 | 取值 |
| --- | --- |
| 服务 | DeepSeek 官方，OpenAI 兼容接口 `{deepseekBaseUrl}/chat/completions` |
| 模型 | `secrets.local.json` 的 `deepseekModel`（当前 `deepseek-flash`），不写死在代码里；上线前按官方文档核对模型名 |
| 参数 | `temperature: 0.2`，`max_tokens: 300`，`stream: false`，不开思考模式 |
| 超时 | HTTP 12 秒；云函数 `timeout` 已是 20 秒。超时或报错回「魔镜开小差了，稍后再试」，日志记 `error` |
| 密钥 | **已接好**：`deploy-cloud.js` 把 `secrets.local.json` 的 `deepseekApiKey` / `deepseekBaseUrl` / `deepseekModel` 写进 `cloudfunctions/api/subscribe.local.js`（已 gitignore）随函数上传；云函数里直接用 `deepseekConfig()` |

### 提示词

`system`（固定不变，放最前，便于前缀缓存）：

> 你是「魔镜」，周三快乐足球联队小程序的助手。只根据下面的说明书和本次附带的数据回答。
> 说明书里没有的功能，就说小程序做不到。人数、时间、天气、榜单只能用附带数据，没有就说查不到，不要猜。
> 提问人不是管理员时，管理员操作只说「请找管理员」。与本小程序无关的问题，礼貌说只能回答球局相关的事。
> 先给结论或该点哪里，再用一句白话说明。不提接口名、字段名。100 字以内。
>
> 【说明书】
> （整份 `doc/mirror.md`，去掉 HTML 注释）

`user`（每次拼装）：

```
【现在】2026-10-31 周六 13:55（北京时间）
【提问人】张三，jiong 路青少年，普通队员，已建档
【上一轮】问：怎么报名 / 答：首页点「去报名」……
【数据】
下一场：养生球，周三 20:00，界龙足球基地；报名方式：分队；你：未报名；名额：jiong路 9/11 后补0，浦东 11/11 后补2
【问题】那人满了还能报吗
```

没有的段落整段省略。

## 7. 限流与预算

- 每人自然周（上海时区周一至周日）问答额度：普通队员 **15**、管理员 **50**、授权人（超管）**100**。FAQ 与模型成功都计次。
- 模型失败（无有效 key、空答、调用异常）仍写 `mirror_logs`，但 `counted: false`，不扣次。
- 悬浮球旁显示「剩 N」；半屏标题下显示「本周还可问 N / 额度 次」。
- 用尽后提示下周再来；不计次、不写计次日志。
- 计数用 `mirror_logs` 的 `weekKey` + `counted: true`。

答法要求精简：FAQ 口语短句；模型提示词要求尽量 60 字以内。

## 8. 日志与质量

### 日志 `mirror_logs`

`createdAt`、`openid`、`question`、`hitId`（命中的 FAQ，没命中为空）、`topScore`、`secondScore`、`fetched`（查了哪些数据）、`usedModel`、`answer`、`error`、`useful`（true / false / 空）。

### 评测集（质量的主要保障）

- 新建 `codeBase/scripts/mirror-eval.json`：30～50 条问法，每条写期望结果（命中哪个 FAQ id，或 `model`）。
- 必须包含容易撞车的对子，例如：
  - 「我有几次鸽子」→ `stats-me`；「取消会记鸽子吗」→ `signup-cancel-pigeon`
  - 「我报名了吗」→ `next-signed`；「怎么报名」→ `signup-how`
  - 「周三去不了咋整」→ `model`（或取消类 FAQ），不能被当成无关问题
- 用 `node --test` 写成单测，纳入 `npm test`，只测 FAQ 匹配和路由，不连云、不调模型。
- 每周看一次 `useful: false` 和走了模型的问题：高频问法补进 FAQ 和评测集，答错的修 `mirror.md`。

## 9. 实现顺序

1. **纯规则**：FAQ 归一化与打分（含分差）、数据路由、时间范围与球队识别、模板填充与兜底；写评测集单测，`npm test` 跑绿。
2. **数据**：从 `homeSummary` 抽出统计公共函数；实现 `next` / `weather` / `stats` / `me-stats` 的紧凑文本。
3. **云函数**：`api` 增加 `mirrorAsk`（已登录）：FAQ → 限流 → 查数 → 调 DeepSeek（`deepseekConfig()`）→ 写日志；`deepseekApiKey` 为空时直接回「魔镜暂未开通」。
4. **前端**：悬浮球组件 + 半屏对话 + 快捷问题 + 打字机 + 有用/没用（`api` 增加 `mirrorFeedback`）。
5. **收尾**：`codeBase/scripts/smoke-test.js` 加 `mirrorAsk` 检查（FAQ 命中「取消会记鸽子吗」、实时「下一场什么时候」、不命中走模型且回答非空）；跑 `/doc-anchored` 对齐 `features.md`、`smoke-tests.md`。

## 10. 维护

改功能时按这个顺序同步：`features.md` → `mirror.md` 对应模块 → 同模块 FAQ → 评测集里相关问法。

## 11. 不做

- 不上向量库、embedding、LangChain、整库 RAG；以后问法真的很散再考虑，且只检索 FAQ。
- 不上 Function Calling、多轮 Agent（一次提问只调一次模型）。
- 一期不做真流式（SSE / 云托管）。
- 不靠关键词硬拒绝问题，无关问题交给模型判断。
- 不把原始 JSON、头像链接放进提示词。
- 不在回答里逐步教普通队员做管理员操作。
- 不把 API Key 放进小程序包或文档。
